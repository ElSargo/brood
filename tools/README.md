# Tools

Development tools and experiments will live here.

Possible tools:

- protocol inspectors
- latency benchmarks
- surface import probes
- renderer demos
- CEF/EGL spikes
- WSL graphics diagnostics

## Smoke Test

Run `./tools/manifold-behavior-probe.sh` to start Manifold with a strict dmabuf-capable test client and emit JSONL behavior telemetry. It defaults to `vkcube --wsi wayland --c 120000 --width 640 --height 360`, captures the client's `WAYLAND_DEBUG` trace, samples `manifoldd status-json`, and logs `window_size_request`, `client_surface_commit`, `client_frame_requested`, `client_frame_callback_done`, `status_sample`, `input_counter_advanced`, and `frame_pacing_sample` events. Use `--duration`, `--sample-interval`, `--out-dir`, or pass a custom client after `--`.

Run `./tools/profile-native-scroll.sh` on a native Linux Wayland session to profile the Smithay presentation path with a real browser autoscroll workload. It builds `manifoldd` with the configured xkbcommon library path, starts an isolated browser profile, drives an auto-scrolling page plus synthetic v120 wheel input, samples `status-json`, and fails if active scrolling drops below the frame/commit fps budgets or if input-to-frame, commit-to-submit, dmabuf, or explicit-sync health regress. It also reports input-to-client-commit, input-commit-to-submit, commit-to-submit, client-frame-callback-to-commit, client-frame deferrals, and the ratio of visible input frames that had a client commit before Manifold submit. `MANIFOLD_NATIVE_SCROLL_MIN_INPUT_COMMIT_FRAME_RATIO` defaults to `0.75` to protect same-frame ordering, and `MANIFOLD_NATIVE_SCROLL_MAX_COMMIT_TO_FRAME_P95_US` defaults to `8000`. It defaults to the Brave Flatpak and can be pointed at another browser with `MANIFOLD_NATIVE_SCROLL_BROWSER_CMD`.

Run `./tools/dev-nested-manifold.sh --keep-running --capture` to start a stable Manifold instance, spawn a development Manifold instance inside it, launch a real client inside the dev instance, sample both `status-json` streams, and optionally capture the stable presentation window with WSLg `PrintWindow`. This is the first harness for developing and testing Manifold inside itself. See [Nested Development Harness](../docs/nested-dev-harness.md).

Run `./tools/audit-v1-capabilities.sh` from the repo root for the concise v1 acceptance audit. It first runs formatting, offline checking, unit tests, and the headless compositor proof checks, then runs the backend dmabuf classifier and each host-backed v1 smoke individually when a host display is available. The output includes `requirement=... result=... evidence=...` lines for the v1 requirements; each requirement points at the specific smoke logs that prove it, so one host-input or visual failure does not obscure unrelated requirements. A result of `overall=pass_with_capability_skips` means the implemented v1 behavior passed but the current backend skipped positive dmabuf or fence validation with `rc=77`; the audit also emits `capability_completion=incomplete_backend_capability_skips` plus `capability_backend_*` lines from `./tools/diagnose-dmabuf-backend.sh` in this case. A full no-skip backend emits `capability_completion=complete` with `overall=pass`. Set `MANIFOLD_AUDIT_REQUIRE_NO_SKIPS=1` on a DRM-capable backend to make any capability skip fail the audit while still printing the backend classification. If the host presentation socket is unavailable, the audit still reports Rust baseline and headless requirement results; if those checks pass it stops with `overall=blocked_host_display_unavailable`, and if any runnable check failed it reports `overall=fail ... host_display=unavailable` instead.

Run `./tools/smoke-audit-strict-mode.sh` to verify strict audit behavior. It runs `MANIFOLD_AUDIT_REQUIRE_NO_SKIPS=1 ./tools/audit-v1-capabilities.sh` and passes only if a capable backend completes with zero skips, or if a limited backend rejects capability skips with `overall=fail_capability_skips_disallowed`. It exits `77` when no host display is available.

Run `./tools/smoke-audit-blocked-host.sh` to force a missing host display and verify the audit's blocked-host branch. It requires Rust baseline checks, headless compositor checks, control-error handling, repeated attach-failure handling, dmabuf validator fixtures, and dmabuf backend classifier fixtures to pass, requires host-backed requirements to report `result=blocked`, verifies the host display diagnostic block names the missing Wayland/X11 sockets, and then injects a runnable `cargo fmt` failure to prove `overall=fail ... host_display=unavailable` takes precedence over the host block.

Run `./tools/smoke-v1-full.sh` from the repo root for the full v1 proof suite: formatting, offline build/test, dmabuf validator/classifier fixtures, headless Wayland globals, headless native-client mapping, headless input forwarding, headless control-error handling, headless JSON status, headless status parity, headless client exit, headless multi-client lifecycle, headless multi-client input focus, headless attach diagnostics, headless presentation-close idempotency, headless repeated attach-failure handling, startup attach fallback, native nesting, detach/reattach, input forwarding, WSLg host pointer input, JSON status, WSLg visual capture, WSLg close/resume, WSLg attach/detach idempotency, WSLg host-close input, WSLg resume input, WSLg resume stress, dmabuf diagnostics, explicit-sync diagnostics, and latency/cadence.

The full suite and compositor smoke scripts require a host display socket for the Winit presentation endpoint. Under WSLg this is normally `$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY`; X11 fallback checks `/tmp/.X11-unix` and `/mnt/wslg/.X11-unix`. If preflight fails, the log includes `host_display_diagnostic=begin...end` with the socket paths, environment, directory listings, and WSLg log availability. If an unusual backend is available but these socket checks do not detect it, set `MANIFOLD_SKIP_HOST_PREFLIGHT=1` to let `manifoldd` attempt startup directly. The headless smoke scripts can still be run individually when no host display is available.

Run `./tools/smoke-manifoldd.sh` from the repo root to build `manifoldd`, launch a real nested Wayland client, verify frame/commit progress, detach the presentation window without closing the nested window, reattach it, and validate dmabuf advertisement diagnostics.

Set `MANIFOLD_SMOKE_CLIENT=/path/to/client` to test a specific native Wayland app. By default the script uses `weston-simple-egl`, falling back to `weston-terminal` when available.

Run `./tools/smoke-headless-attach-diagnostics.sh` to start `manifoldd --headless`, request presentation attach against an intentionally invalid host display, and verify status reports `presentation_attach_failures` plus `presentation_last_error` while the session process remains controllable.

Run `./tools/smoke-headless-frontend-close-idempotent.sh` to start `manifoldd --headless`, launch a real SHM Wayland client, issue `close-frontend`/`frontend-close` while already detached, and verify the nested app remains mapped without incrementing attach/detach counters or recording presentation latency. It then requests an attach against the intentionally missing host display and verifies the failed attach does not count as an applied attach.

Run `./tools/smoke-headless-repeated-attach-failure.sh` to start `manifoldd --headless` with a real SHM Wayland client and an intentionally missing host display, retry presentation attach twice, and verify each failed attach increments `presentation_attach_failures` while leaving the nested app mapped, applied attach/detach counters unchanged, runtime redraw failures at zero, and attach latency fields unset.

Run `./tools/smoke-startup-attach-fallback.sh` to start `manifoldd` without `--headless` against an intentionally invalid host display, launch a real nested SHM Wayland client, and verify the session process continues detached with the nested client mapped and committing.

Run `./tools/smoke-headless-wayland-info.sh` to start `manifoldd --headless`, inspect its nested Wayland globals with `wayland-info`, and verify `wl_compositor`, `wl_shm`, `wl_seat`, `xdg_wm_base`, `XRGB8888`, and `ARGB8888` are available before any presentation endpoint attaches.

Run `./tools/smoke-headless-native-client.sh` to start `manifoldd --headless`, launch a real SHM Wayland client, verify it maps an xdg toplevel and commits buffers, verify center-motion targets the nested surface, then request presentation attach against an invalid host display and verify the nested app remains mapped.

Run `./tools/smoke-headless-input-forwarding.sh` to start `manifoldd --headless`, launch `weston-eventdemo`, inject pointer, button, key, and axis events through the control socket, and assert that the nested Wayland client logs the forwarded events. This verifies compositor seat forwarding without a host display socket.

Run `./tools/smoke-headless-control-errors.sh` to start `manifoldd --headless`, launch a real SHM Wayland client, send malformed, oversized, and idle raw control-socket commands, and verify each returns `ERR` while the session process remains responsive, the nested app stays mapped, and attach/detach/input counters do not change.

Run `./tools/smoke-headless-status-json.sh` to validate `status-json` schema and headless invariants while a real SHM Wayland client is mapped and targeted by injected center-motion.

Run `./tools/smoke-headless-status-parity.sh` to validate that text `status` and `status-json` expose the same public fields and compatible values while a real SHM Wayland client is mapped. This catches telemetry drift where a field is added to one status surface but not the other.

Run `./tools/smoke-headless-client-exit.sh` to start `manifoldd --headless`, launch a real SHM Wayland client, verify it maps, focus it with injected pointer input, kill that client, and verify the lifecycle timer refreshes stale windows back to zero while clearing stale focus.

Run `./tools/smoke-headless-multi-client.sh` to start `manifoldd --headless`, spawn two real SHM Wayland clients through the control socket, verify both map, focus nested surfaces, then kill the clients one at a time and verify the lifecycle timer drops the window count from two to one to zero while stale focus is repaired and then cleared.

Run `./tools/smoke-headless-multi-client-input-focus.sh` to start `manifoldd --headless`, spawn two real `weston-eventdemo` clients, click/key the newer top window, then click/key the exposed strip of the older window. It verifies key events route only to the focused client in each step and that pointer/button/key counters reflect both routed input batches.

Run `./tools/smoke-input-forwarding.sh` to launch `weston-eventdemo`, inject pointer/key/axis events through Manifold's control socket, and assert that the nested Wayland client logs the forwarded events. This isolates compositor seat forwarding from WSLg host-window input quirks.

Run `./tools/smoke-wslg-host-input.sh` to launch `weston-eventdemo`, send real Windows pointer, click, and keyboard events to the exported WSLg Manifold window, and assert that the nested Wayland client logs the forwarded focus, button, and key events.

Run `./tools/smoke-status-json.sh` to launch a real nested Wayland client, inject targeted pointer input, request both `status` and `status-json` over the control socket, and validate attached schema parity, visible input-to-frame telemetry, core runtime invariants, and dmabuf diagnostic invariants.

Run `./tools/smoke-wslg-visual.sh` to launch a real nested Wayland client, capture the exported WSLg Manifold window with Windows `PrintWindow`, save a PNG, and sample pixels to reject blank captures before and after control detach/reattach.

Run `./tools/smoke-wslg-close-resume.sh` to attempt a host `WM_CLOSE` against the exported WSLg Manifold window, then verify presentation close/resume behavior while the nested client remains alive. The script reports `host_wm_close_delivered=yes|no`; when WSLg does not deliver `WM_CLOSE`, it falls back to `ctl close-frontend` to exercise the compositor close path safely. The measured close detach latency is checked against `MANIFOLD_MAX_CLOSE_DETACH_LATENCY_US`, reattach-to-first-frame latency is checked against `MANIFOLD_MAX_CLOSE_REATTACH_LATENCY_US`, client frame callbacks must progress after reattach, and the reopened window is captured with `PrintWindow` to reject blank output; both latency budgets default to 75000 microseconds.

Run `./tools/smoke-wslg-attach-detach-idempotent.sh` to launch a real nested Wayland client, verify repeated `attach` requests while the presentation window is already attached do not increment attach/detach counters, detach the presentation window once, verify repeated `detach`/`close-frontend`/`frontend-close` requests while already detached do not increment counters or kill the nested window, then reattach and repeat the attached-idempotency check. Applied detach and reattach-to-frame latency are checked against `MANIFOLD_MAX_IDEMPOTENT_DETACH_LATENCY_US` and `MANIFOLD_MAX_IDEMPOTENT_REATTACH_LATENCY_US`, each defaulting to 75000 microseconds.

Run `./tools/smoke-wslg-detached-client-exit.sh` to launch a real nested Wayland client, focus it, detach the presentation window, terminate the nested client while the presentation window is closed, verify Manifold's lifecycle timer drops the stale window and clears stale focus while still detached, then reattach and verify the presentation window resumes with zero nested windows instead of resurrecting stale state. It then spawns a fresh native client into the resumed presentation window and verifies pointer/key input plus visible input-to-frame telemetry still advance.

Run `./tools/smoke-wslg-detached-spawn-resume.sh` to detach the presentation window before any nested client is mapped, spawn a real native Wayland client through the control socket while detached, verify it maps and commits while the presentation window remains closed, then reattach, require client frame callbacks to resume, inject input into the reattached nested window, require visible input-to-frame telemetry, and capture the reopened presentation window with `PrintWindow`.

Run `./tools/smoke-wslg-host-close-input.sh` to launch `weston-eventdemo`, verify input forwarding, close the presentation window with host `WM_CLOSE`, reattach it, and verify another input batch reaches the same nested client after resume. It falls back to `ctl close-frontend` when WSLg does not deliver `WM_CLOSE`. Detach, reattach state, and reattach-to-first-frame latency are checked against `MANIFOLD_MAX_CLOSE_DETACH_LATENCY_US` and `MANIFOLD_MAX_CLOSE_REATTACH_LATENCY_US`, each defaulting to 75000 microseconds.

Run `./tools/smoke-wslg-resume-input.sh` to launch `weston-eventdemo`, verify forwarded pointer/key/axis events, detach and reattach the presentation window, then verify another input batch reaches the same nested client after resume. The script also checks measured control detach, reattach state, and reattach-to-first-frame latency against `MANIFOLD_MAX_RESUME_DETACH_LATENCY_US` and `MANIFOLD_MAX_RESUME_ATTACH_LATENCY_US`, each defaulting to 75000 microseconds.

Run `./tools/smoke-wslg-resume-stress.sh` to repeatedly detach and reattach the presentation window while a real nested Wayland client stays mapped. Each cycle requires presentation frame progress, client frame callback progress after reattach, and detach/attach-to-frame latency within budget. Set `MANIFOLD_RESUME_STRESS_CYCLES` to change the default five-cycle run; `MANIFOLD_RESUME_STRESS_MAX_DETACH_LATENCY_US` and `MANIFOLD_RESUME_STRESS_MAX_ATTACH_LATENCY_US` default to 75000 microseconds.

Run `./tools/smoke-dmabuf-diagnostics.sh` to compare Manifold's dmabuf status fields with a nested client's `WAYLAND_DEBUG` trace. It verifies that dmabuf is not advertised when the renderer reports zero importable dmabuf formats, and that positive dmabuf format support appears in the protocol trace.

Run `./tools/smoke-explicit-sync-diagnostics.sh` to inspect Manifold's nested Wayland globals with `wayland-info` after presentation attach. It verifies that `zwp_linux_dmabuf_v1` and `wp_linux_drm_syncobj_manager_v1` are advertised exactly when the corresponding status fields report `dmabuf=v3|v4` and `explicit_sync=v1`, and absent when the status fields report disabled paths.

Run `./tools/diagnose-dmabuf-backend.sh` to classify the current presentation backend for DMA-BUF validation. It prints the status fields that decide whether this host is a fallback-only backend (`dmabuf_formats=0`), a dmabuf-v3 backend without v4 feedback, a dmabuf-v4 backend without explicit sync, or a DRM-capable backend that should run the strict no-skip audit. Under the current WSLg backend it reports `classification=fallback_no_dmabuf_import` because WSLg exposes no importable dmabuf texture formats to the Winit/GLES presentation renderer.

Run `./tools/test-dmabuf-backend-classifier.sh` to test that backend classification table without depending on the current GPU. It covers fallback-only, full DRM-capable, dmabuf-v4-without-sync, dmabuf-v3-without-feedback, incoherent, and invalid-input cases. The v1 audit runs this before host preflight so classifier regressions are caught even without a host display.

Run `./tools/validate-dmabuf-positive.sh` on a backend with importable dmabuf formats to prove the positive path. It launches `weston-simple-dmabuf-egl --explicit-sync=0` by default, requires `dmabuf=v3|v4`, requires a positive integer `dmabuf_formats` count, checks the import client protocol trace for `zwp_linux_dmabuf`, and requires at least one accepted dmabuf import plus non-empty last-import telemetry. When v4 is advertised it also launches `weston-simple-dmabuf-feedback` and requires actual `zwp_linux_dmabuf_feedback_v1` events, not just a registry string. It exits `77` with a `SKIP` message when the renderer reports `dmabuf_formats=0`, which is expected under the current WSLg backend, but only after verifying that Manifold did not advertise dmabuf or syncobj globals and did not record import attempts, blocker installs, or blocker errors.

Run `./tools/test-dmabuf-status-validator.sh` to test the status/trace validator used by positive dmabuf validation. It covers coherent backend skips, disabled-path protocol leaks, v3/v4 diagnostic consistency including default-feedback fallback reasons, v4 rejection of stale v3-only explicit-sync disabled reasons, malformed or missing positive-path counters, rejected imports, missing readiness blockers, syncobj trace mismatches, strict explicit-sync release-point failures, implicit-fallback rejection, and strict explicit-sync success fixtures. The v1 audit runs this check before any host-display-dependent checks so the validator logic is covered even on WSLg backends that cannot exercise positive dmabuf imports.

Set `MANIFOLD_DMABUF_REQUIRE_EXPLICIT_SYNC=1 ./tools/validate-dmabuf-positive.sh` on a presentation path with an EGL render node that supports `syncobj_eventfd` to validate fence correctness too. In this mode the script launches `weston-simple-dmabuf-egl --explicit-sync=1`, requires `explicit_sync=v1`, requires `explicit_sync_disabled=none`, and checks the client protocol trace for `wp_linux_drm_syncobj`. Custom clients can be provided with `MANIFOLD_DMABUF_IMPORT_CLIENT` and `MANIFOLD_DMABUF_IMPORT_ARGS`, but the strict mode still requires the trace to prove syncobj use.

The current WSLg Winit/GLES presentation backend reports `explicit_sync=none` with `explicit_sync_disabled=no_dmabuf_texture_formats` after presentation attach because WSLg exposes no importable dmabuf formats here. Headless status still reports `winit_backend_no_drm_import_device` before any presentation backend has attached. On a capable EGL/DRM backend, Manifold opens the render node, verifies `syncobj_eventfd`, advertises `linux-drm-syncobj-v1`, and installs commit blockers so explicit acquire points and implicit dmabuf readiness delay surface commits until the buffer is safe to read.

The `status` and `status-json` outputs include `wayland_client_insert_errors`, `wayland_dispatch_errors`, `xdg_configure_errors`, `presentation_runtime_failures`, `focus_clears`, `focus_repairs`, `window_lifecycle_refreshes`, `window_lifecycle_focus_clears`, `window_lifecycle_focus_repairs`, `client_frame_deferrals`, `client_deferred_frames`, `input_frame_deferrals`, `input_deferred_frames`, `last_input_to_frame_us`, `max_input_to_frame_us`, `last_input_to_submit_us`, `max_input_to_submit_us`, `input_commit_frame_count`, `input_without_commit_frame_count`, `last_input_to_commit_us`, `max_input_to_commit_us`, `last_input_commit_to_submit_us`, `max_input_commit_to_submit_us`, `last_commit_to_frame_us`, `max_commit_to_frame_us`, `last_commit_to_submit_us`, `max_commit_to_submit_us`, `last_client_frame_callback_to_commit_us`, `max_client_frame_callback_to_commit_us`, `last_attach_to_frame_us`, `max_attach_to_frame_us`, `dmabuf_explicit_sync_release_points`, `dmabuf_explicit_sync_blockers`, `dmabuf_implicit_blockers`, `dmabuf_blocker_failures`, and `dmabuf_last_blocker_error`. Resume validation uses the attach-to-frame fields to prove the reopened presentation window reaches a rendered frame within budget. Visible smoothness validation uses input-to-frame and commit-to-frame fields to prove targeted input and client updates reach a presentation frame; input-to-commit and input-commit-to-submit fields show whether a visible input batch had a client commit available before Manifold submitted that frame. Headless, detached, or untargeted input/commits are counted but do not create visible latency samples. The v1 audit's `low_latency_cadence` requirement is backed by the dedicated latency/cadence smoke plus close/resume, host-close input, resume input, and resume stress smokes so lifecycle detach/reattach latency is covered as well. Positive dmabuf validation requires at least one blocker and no blocker failures; strict explicit-sync validation requires at least one explicit sync blocker and at least one observed release point.

Run `./tools/smoke-latency-cadence.sh` to launch a real nested client, inject input, and verify frame cadence, input-to-frame latency, and visible client commit-to-frame latency. Thresholds are configurable with `MANIFOLD_MAX_FRAME_INTERVAL_US`, `MANIFOLD_MAX_INPUT_TO_FRAME_US`, and `MANIFOLD_MAX_COMMIT_TO_FRAME_US`.
